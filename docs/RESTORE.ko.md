# 복원

워크스페이스 영속과 복원. [ARCHITECTURE.md](ARCHITECTURE.md)의 하위 문서다. 영문 정본: [RESTORE.md](RESTORE.md) — 어긋나면 영문이 우선한다.

재시작하면 워크스페이스가 있던 그대로 돌아온다: 창은 제 위치에, 탭과 분할은 그 구조로, 각 터미널은 마지막 작업 디렉토리에서, 가능하면 셸이 그대로 돌던 채로. 아래 원칙이 그 전 경로를 지배한다.

## 복원 사다리

복원되는 터미널 pane 은 가능한 가장 높은 단을 탄다. 판정은 앞단만 추가한다 — repaint 경로 자체는 한 경로로 유지된다(R-PATH).

1. **live adoption** — 같은 앱 프로세스가 살아있는 PTY 를 remount 한다(한 실행 안의 이동 remount). 아무것도 다시 그리지 않는다.
2. **warm reattach** — `soksak-ptyd`(코어 workspace 의 독립 바이너리, identity 홈 `bin/` 에 스테이징)가 모든 셸을 소유하므로 셸과 그 자식은 앱 종료를 넘어 같은 pid 로 생존하고, 데몬은 단조 시퀀스를 붙인 raw 출력 링을 소유한다. 같은 pane id 의 재스폰은 스폰 대신 데몬 소켓에 재부착한다. 화면은 플러그인이 선택한 터미널 엔진 유닛(`soksak-sidecar-terminal-<engine>`, 터미널 도메인 — 코어 데몬이 아니다. 기본은 `-alacritty`, `-wezterm`·`-vt100`·`-ghostty` 가 같은 계약을 구현한다)이 다시 그린다: 사이드카가 데몬의 세션별 tee 를 VT 미러로 소비하고 `rehydrate{window,pane}→{paint,uptoSeq,altActive}` 를 서비스한다 — 스크롤백·보이는 화면·alt-screen 내용·private mode·커서가 미러 그리드에서 SGR 런으로 합성된다. pane 은 그것을 그린 뒤 데몬 raw 스트림을 `uptoSeq` 부터 부착한다; 시퀀스 경계가 핸드오프를 레이스-프리로 만든다. 합성 페인트는 바이트 재생이 아니므로 프론트 xterm 이 두 번 답할 DA1/DSR 질의가 실릴 수 없고(미러는 절대 응답하지 않는다), `uptoSeq` 이후 raw 꼬리의 질의는 진짜 미응답 질의라 라이브 터미널이 한 번 답한다. 바이트 생존·링·재부착은 데몬(코어 배관)의 것, 화면 합성은 사이드카(터미널 도메인)의 것이다. 명시 종료는 detach 만 한다 — 데몬 세션을 죽이지 않는다.
3. **cold byte restore** — 데몬은 내용 불가지 봉인-블롭 저장소를 소유하고, 체크포인트 *정책*(언제·무엇을 직렬화할지)은 터미널 엔진 유닛의 것이다. 사이드카가 세션의 평면화된 화면 페인트를 직렬화해 데몬에 push 하면, 데몬이 앱 소유 X25519 공개키(`soksak-seal` sealed box, 개인키는 vault 에만)로 봉인해 `<home>/pty/checkpoints` 에 tmp+rename 으로 쓴다. 사이드카의 디바운스(출력 이벤트 idle 300ms·상한 5s). 데몬은 블롭의 바이트를 읽지 않는다 — 봉인과 원자 쓰기는 데몬, 의미는 사이드카가 쥔다. 정상 세션 종료는 파일을 지우므로, 살아남은 체크포인트는 데몬 자신의 죽음의 증거다. 그 pane 의 다음 스폰에서 앱이 — vault 가 unlock 일 때만 — 봉인을 열어 기록을 비활성 텍스트로 다시 그리고(활성이던 alt-screen 은 텍스트 흐름으로 평면화한다: 죽은 세션의 TUI 는 라이브 화면이 아니라 잔상이다), 해소된 소실 고지("봉인 체크포인트에서 복원 — 실행 중이던 프로세스는 소실")를 찍고, 소비한 파일을 지운다. 화면 바이트 평문은 디스크에 닿지 않는다 — 잠금 중에는 파일이 봉인된 채 남고 이 단은 blocks repaint 에 양보한다.
4. **blocks repaint** — 최근 명령 블록을 비활성 텍스트로 다시 그린다(R-PATH). vault 잠금 중의 유일한 단이자, 위 단이 전부 불가할 때의 바닥이다.

## 데몬 무중단 판올림(handoff)

`pty.daemon.upgrade` 는 셸 하나 건드리지 않고 새 `soksak-ptyd` 세대로 넘어간다: 도는 데몬이 새 바이너리를 스테이징하고, 각 세션의 PTY master fd 를 fd 상속으로 후임에게 넘긴 뒤 물러난다. 커널의 fd refcount 가 master 를 살려 두므로 어떤 셸도 SIGHUP 을 보지 않는다. 이것을 성립시키는 불변식은 셋이며, 셋 다 잃어보고 배운 것이다.

- **H-FD — 어떤 복사도 아직 필요한 값을 파괴하지 않는다.** 인계 fd 는 모든 대상이 모든 원본과 ack 채널보다 크도록 계획한다(`plan_handoff_fds`). `dup2` 는 대상을 먼저 닫는다 — 대상을 `4..N` 으로 못박았더니 데몬이 이미 들고 있던 master 원본을 덮어써, 복사되기 전에 master 를 파괴하고 그 셸을 죽였다. 세션 순회 순서는 해시맵의 것이라 이 충돌은 간헐로만 드러났다.
- **H-SEQ — 인계받은 링은 이전 좌표에서 이어 센다.** 스냅샷이 `ring_seq` 를 나르고 후임이 거기서 이어받는다(`RawRing::resumed`). 0 부터 다시 세면 재부착하는 클라이언트를 영원히 "이미 최신"으로 판정한다: 셸은 살아 입력도 받는데 출력만 조용히 사라진다.
- **H-REATTACH — 부착 스트림의 끝은 셸의 끝이 아니다.** 물러나는 데몬은 모든 부착을 놓으므로 스트림마다 EOF 가 온다. 생사는 권위에게 묻는다 — 앱은 세션이 아직 목록에 있는지 묻고, 있으면 자기가 세어 온 커서에서 다시 붙는다(`attach` 응답이 `seq` 를 싣는다: 그 응답을 다 소비하면 클라이언트가 서 있는 좌표). ping 만으로는 "셸이 끝났다"와 "데몬이 물러났다"를 가를 수 없다 — 둘 다 응답한다.

- **H-ASK — 못 하는 상대에게 시키지 않는다.** 인계 계획은 **물러나는** 데몬이 그린다. 그래서 새 바이너리를 스테이징해도 지금 도는 판이 안전해지지 않는다. 앱이 먼저 묻는다 — 데몬이 `Ping` 에 `handoffContract` 를 선언하고(없음 = 계약 이전), `pty.daemon.upgrade` 는 조치 하나를 문구에 담아 거절한다(한 번만 재시작). 수준은 `pty.daemon.status` 의 `handoffContract`/`handoffContractRequired` 로 읽히므로, 판올림 가능 여부를 셸을 잃어 가며 알아내지 않는다. 뒤도 확인한다: 같은 pid 가 여전히 대답하면 아무것도 넘어가지 않은 것이라 성공이라 말하지 않는다.

모든 경계는 활동 피드에 남는다: `pty.stream.ended`·`pty.stream.reattached`·`pty.session.gone`·`pty.stream.reattach.failed`·`pty.daemon.upgrade.refused`. 멎은 pane 은 언제나 원장으로 읽혀야 하며 소스 추론으로 좁히는 일이 없어야 한다. 게이트는 `scripts/e2e/pty-handoff.mjs` 다 — 모든 터미널 엔진을 반복 판올림으로 순회하며 같은 셸이 재적재 없이 계속 대답하는지 단언한다.

데몬을 스테이징/연결하지 못하면 터미널은 in-process PTY 로 폴백한다 — 데몬 이전의 동작 그대로 — 그리고 앱이 activity 피드로 격하를 고지한다(`pty.daemon.fallback`). 데몬 사망도 같은 방식으로 고지된다(`pty.daemon.lost`). 무음 격하는 금지다.

## 원칙

### R-OWN — 소유권 위임

모든 히스토리는 소유자가 정확히 하나이고, soksak 은 그것을 복제하지 않는다.

- 쉘 히스토리는 터미널 플러그인이 `app.data` records(`command_blocks`, 프로젝트 scope)의 명령 블록으로 소유한다. 완료된 명령 1건 = 블록 1건: 명령줄·출력·cwd·종료코드·시각.
- TUI 내부 히스토리(claude, codex)는 TUI 자신의 세션 파일이 소유한다. soksak 은 계보 링크(pane↔세션 id)만 fs-watch 관찰로 기록하고, 전사를 복제하지 않는다.
- 워크스페이스 스냅샷은 구조만 소유한다: 프로젝트·컨텐츠·분할·뷰 파라미터.

### R-PATH — 재수화 경로는 하나

재시작 복원과 vault unlock 재수화는 같은 코드를 지난다: 그 뷰의 블록을 조회해 dim `[복원됨]` 마커 아래 비활성 텍스트로 다시 그린다. 아무것도 재실행하지 않는다. 인증된 세션 계보가 있는 블록은 이어가기 어포던스(`sok terminal.resume {…}`)를 보여주고, 실행은 사용자의 행위다. vault 잠금 중 저장된 블록은 미인증이라 이어가기를 제안하지 않는다.

### R-EVIDENCE — 활동 시각은 이벤트가 근거

뷰별 `lastActivity` 는 증거가 있을 때만 갱신된다: 명령 시작·종료, 턴 종료, 뷰 활성화, PTY 출력(pane 당 스로틀). 샘플링과 추정은 없다. 관찰된 cwd 도 같은 방식으로 쉘 통합 OSC 이벤트에서 영속된다.

### R-ATOMIC — 외형은 원자적, 자원은 지연

복원된 창은 모든 탭과 분할을 한 번에 그린다. 화면에 실제로 보이는 뷰만 본문을 즉시 마운트하고, 가려진 뷰는 cold 로 남았다가 드러나는 순간 또는 1회성 idle 체인이 `lastActivity` 순으로 승격한다. 채워지는 과정은 보이지 않는다.

### R-CLEAN — 정합성

- 명시 종료(Cmd+Q / `app.exit`)는 전 창 세션을 보존한다 — 데몬 소유 셸은 detach 된 채 계속 돈다. 사용자의 개별 창 닫기는 그 창의 스냅샷·manifest slot·PTY 세션을 폐기한다(`kill_by_window` 가 그 창의 데몬 셸을 거둔다 — 창보다 오래 사는 유령 셸 없음) — `CloseRequested` 에서 마크, `Destroyed` 에서 정리하므로 unload 의 마지막 저장이 그것을 부활시키지 못한다.
- 자동 저장은 디바운스되고 `pagehide` 에서 flush 된다. 창 이동·리사이즈도 저장을 트리거한다.
- 런타임에 만든 창은 `fresh=1` 로 부팅하며 라벨로 복원하지 않는다 — 재사용되는 `win-<seq>` 라벨이 crash 로 남은 세션을 되살리면 안 된다.
- 프로젝트 root 가 없으면 탭을 지우지 않고 격하한다(배너, 휘발 플래그).

## 멀티윈도우

manifest(core kv `windows`)는 워크스페이스 창마다 slot 하나를 담는다: 라벨·root 목록·활성 root·논리 프레임, 그리고 마지막 포커스 라벨. `main` 은 컨트롤 플레인(NAMING 4b)이라 워크스페이스 스냅샷을 갖지 않고, 프레임은 자체 키(`controlPlaneFrame`)로 영속된다. 부트 시 컨트롤 플레인이 manifest 의 전 slot 을 스폰하고(스냅샷 없는 유령 slot 은 정리), 마지막 포커스 창을 앞으로 가져오며, 진짜 첫 실행(slot 0·recents 0)이면 기본 프로젝트 워크스페이스 창을 하나 연다. 리스폰은 `w-*` slot 만 스폰한다(NAMING 4b): 다른 라벨의 slot 은 시끄러운 오류와 함께 거부하고 데이터는 건드리지 않는다 — capability 스코프 밖이라 그런 창은 귀머거리로 부팅된다(전 소켓 명령 타임아웃). 구세대 데이터는 깃 추적 일회용 마이그레이션 `scripts/migrations/20260704-window-label-uuid.sh`(win-<seq> → uuid)와 `scripts/migrations/20260705-main-control-plane.sh`(구 main 워크스페이스 → w-<uuid> slot, main 은 워크스페이스 없음)가 한 번씩 교정했다. 리스폰된 각 창은 자기 스냅샷(`window/<label>`)을 단일 복원 경로로 복원하고, 프로젝트 root 는 전역 단일 오픈 레지스트리(P6)를 지나 점유한다.

## 복원 seam

`PluginViewContext.restore { cwd, state }` 가 복원 마운트에서 관찰됐던 런타임 사실을 뷰 제공자에게 전달한다. `cwd` 는 관찰된 작업 디렉토리 — 터미널 플러그인은 프로젝트 root 대신 그곳에서 spawn 하고, 이동 remount 에서는 살아있는 PTY 입양이 여전히 우선한다. `state` 는 뷰가 `setRestoreState` 로 마지막에 보고한 값 — 떠날 때 그대로 돌아와야 할 뷰-로컬 런타임 상태(선택·패널 접힘·활성 탭)다. 뷰 레코드에 영속되며 오직 이 seam 으로만 오간다 — 플러그인 kv 에 viewId 키로 영속하지 마라(viewId 재사용이 죽은 뷰의 상태를 새 뷰에 흘린다). 복원된 참조의 대상이 더 이상 없으면 부활시키지 말고 해제한다.
